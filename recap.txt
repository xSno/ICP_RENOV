Implementation
- Migration 9 preserves migrations 1-8 and rebuilds the shared ContractDocument/Event persistence without data loss. CONTRACT requires revision_index >= 1 and retains unique Rxx/signed-copy semantics. INTERVENTION_SHEET requires revision_index NULL and all signed_pdf_* metadata NULL.
- ContractTemplateVersion adds closed required_intervention_fields metadata. S9 accepts only intervention.technician. Technician remains optional globally and becomes required only for a selected sheet version that declares it.
- INTERVENTION_SHEET templates are selected only by document_kind=INTERVENTION_SHEET and version_status=AVAILABLE. They require neither contract_type_code nor client regimes; CONTRACT, TO_VALIDATE and ARCHIVED versions are excluded. No real production template/version is seeded or promoted.
- The six canonical fields are implemented exactly: intervention.date, technician, other, notes, issues and quote_recommended. Dates render in French, multiline values retain line breaks, booleans render Oui/Non, and empty optional source rows/paragraphs/section headings are removed cleanly.
- A dedicated InterventionSheetGenerationService is separate from CONTRACT generation. It never calls ContractNumberAllocator, creates no Rxx, performs no DRAFT -> TO_SIGN transition, changes no Contract status/number/lifecycle truth, and writes under documents/contracts/<contract>/other/intervention/<document-id>/.
- Context authority is deterministic. With SIGNATURE_RECORDED, the immutable snapshot of the exact signed ContractDocument supplies contract number, client, site and ordered equipment even when a newer unsigned Rxx exists. Otherwise existing Contract-owned snapshots/items are used. Live Client/Site/Equipment masters are never read during sheet generation.
- The immutable sheet snapshot records document kind, internal Contract reference, canonical contract context, ordered equipment, all intervention inputs, company values used, template/source identity/hash, requiredness metadata and the signed-authority reference when applicable. equipment.internal_notes is excluded from snapshots and rendering.
- TemplateSourceStore source_relpath/source_hash verification, document-kind-aware closed field/block/loop preflight, body/header/footer traversal, residual-token checks, required values, DOCX postflight, LibreOffice PDF conversion and PDF postflight are enforced. CONTRACT-only legal/lifecycle blocks are rejected for sheets.
- Known-source OOXML adaptation remains a working-copy transformation. It adds controlled optional structures and a repeatable equipment header without modifying templates/. LibreOffice invocation now uses bounded headless/no-restore/no-lock flags and best-effort isolated-profile cleanup.
- Publication is atomic across DOCX placement, PDF placement, ContractDocument and one DOCUMENT_GENERATED event. Failures remove staged/final partials and leave Contract/Rxx history unchanged. CONTRACT_SENT and SIGNATURE_RECORDED remain CONTRACT-only.
- Documents & suivi keeps Autres documents separate from Révisions contractuelles, exposes Créer une fiche d’intervention, provides the bounded French modal, lists multiple sheets newest first without Rxx, and opens DOCX/PDF through the existing path-safe opener. Missing files preserve history and disable only the missing action.
- Template generation metadata becomes immutable after either CONTRACT or INTERVENTION_SHEET use.
