C3-B3 — External template validation enum/string boundary

Baseline
- Current accepted HEAD: 3918004 (C3-B2 first Windows one-dir build).
- This is a blocking packaged-runtime correction only; no commit is made in this review state.

Root cause and authority
- The affected screen is the native Qt ModelVersionDetail external-validation form, not a WebChannel method.
- PySide6 QComboBox.currentData() returns primitive strings such as "CONFIRMED" even when the item data was supplied as ExternalGateStatus.CONFIRMED.
- ModelVersionDetail._save_external() passed those strings to TemplateCatalogService; TemplateValidationRepository.set_external_content() and set_external_gate() then attempted status.value, causing AttributeError: 'str' object has no attribute 'value'.
- The view catches that exception and displays its text to the user, so the historical failure does not produce a Python traceback in application.log. No logging behavior was changed for this bounded fix.
- TemplateCatalogService now explicitly accepts an existing ExternalGateStatus enum or validates an exact primitive token into that enum before repository persistence. Unknown strings and non-string/non-enum values raise ContractValidationError. TEMPLATE_VALIDATION_MATRIX authority and all availability gates are unchanged.

Controlled vocabulary and projection
- Existing controlled values inspected: NOT_APPLICABLE, TO_REVIEW, CONFIRMED, REJECTED.
- The actual native UI save path was covered for CONFIRMED, NOT_APPLICABLE, and TO_REVIEW across several gate rows; no uncontrolled token is accepted.
- Repository reads continue to rehydrate ExternalGateStatus values deterministically. Qt currentData() continues to project primitive strings for the UI boundary.
- No template was made AVAILABLE during verification.
