IMP-DS-01A.1 — Shell Routing and Native Sidebar Parity

Baseline
- Starting and current HEAD: cee93024117510e2da066ed3eea259765856de72 (IMP-DS-01A establish design system foundation).
- The worktree was clean before this patch. No commit was created.

Root cause and routing correction
- ApplicationShell only registered an external Web landing for Contrats. The permanent Clients navigation therefore selected the hidden legacy Qt Client surface after native Settings.
- Returning to the WebHost only refreshed the bridge, so it preserved its stale CLIENTS page rather than receiving an explicit destination.
- ApplicationShell now owns a bounded external-landing map. Normal permanent Contrats and Clients navigation invokes the registered landing; workflow=True continues to select the legacy Qt workflow surface.
- MainWindow registers Contrats → Web bridge CONTRACTS and Clients & installations → Web bridge CLIENTS. The helper activates WebHost then calls UiBridge.navigate(page), which refreshes the authoritative destination snapshot.
- Paramètres remains the native Qt Settings surface.

Native sidebar parity
- The fixed 232 px sidebar now has a compact ICP product-mark/brand row and secondary Contrats d’entretien text.
- Navigation stays lower in the upper region; existing dark background and orange active marker are preserved.
- Application locale and the authoritative backup summary are grouped in the stretch-anchored bottom status area.

Behavior intentionally preserved
- Legacy Qt views remain available for bounded workflow, fallback and test paths.
- No domain, persistence, backup behavior, service, WebChannel contract, Settings content, or business workflow changed.
- No IMP-DS-01B/C/D work started.
