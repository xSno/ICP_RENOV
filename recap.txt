ICP RENOV - CONTRACT MANAGEMENT APP - S1 MASTER DATA RECAP

Migration and schema
- S0 migration 1 is preserved unchanged; explicit migration 2 adds clients, sites, and equipment.
- Migration 1 -> 2 and reopen are deterministic and idempotent; schema_migrations and PRAGMA user_version report version 2.
- SQLite foreign keys remain enabled. Parent relationships use ON DELETE RESTRICT; no cascade archive or physical-delete workflow exists.
- The client table contains no contract regime column. The equipment table contains internal_notes and deliberately contains no contract observations column.

Domain / repository / service structure
- domain/master_data.py defines explicit immutable drafts, persisted entities, summaries, display names, and rendered structured addresses.
- repositories/master_data.py owns all SQLite queries, including bounded aggregate client counts without a client-list N+1 pattern.
- services/master_data.py owns UUID creation, validation, create/edit, search/list, Archive/Restore, and relationship orchestration.
- The S0 application composition context constructs and injects MasterDataService; UI widgets execute no SQL, open no database connection, and construct no persistence service.
- Structured validation/not-found/persistence errors prevent raw SQLite errors from reaching normal UI messaging.

Client semantics
- Supports only PERSON and ORGANIZATION master classifications.
- PERSON requires first and last name. ORGANIZATION requires its organization name and supports optional legal form, SIRET, billing address, and proposed reusable contact.
- Common structured address, optional phone/e-mail, internal reference/notes, opaque UUID, timestamps, and archived state persist.
- The proposed organization contact is labelled as requiring confirmation in a future contract; it is not a permanent legal signatory.
- Existing party type remains stable during edit. No consumer/non-professional/professional regime is stored or shown.

Site semantics
- Each site belongs to exactly one client and stores its label, structured address, optional contact and access/instruction notes, UUID/timestamps, and archived state.
- A client supports zero, one, or multiple sites. Site creation from the client detail binds the selected client automatically.
- No standalone Sites navigation entry was added.

Equipment semantics
- Each equipment belongs to exactly one site and supports an evolvable equipment-type string, optional brand/model/serial/power/install date/reference/notes, required location, UUID/timestamps, and archived state.
- Optional power must be numeric and non-negative.
- Master internal notes remain separate from future contract observations. No maintenance history, planning, ticketing, or GMAO model was added.

Archive / Restore
- Client, site, and equipment expose Archive and Restore; the application service exposes no Delete operation.
- Archiving a client does not change its sites or equipment. Archiving a site does not change its equipment. Equipment archive affects only that equipment.
- Relationships and counts remain intact throughout archive/restore operations.

Clients & installations UI
- Replaced only the S0 Clients & installations placeholder with a functional PySide6 split workspace.
- Left pane: real search, Actifs/Archivés filter, persisted selectable clients, party label, site/equipment counts, and clean empty state.
- Right pane: selected identity/admin detail, multi-site cards, correctly nested equipment, real empty states, and bounded « Aucun contrat lié » structural reserve.
- Client, Site, and Equipment creation/editing all use the same scrollable right-side drawer embedded inside the Clients & installations workspace; no editor creates a separate native/top-level window.
- Every drawer exposes Enregistrer, Annuler, an explicit Fermer action, and Escape dismissal. Validation keeps the drawer open with entered values intact, while Escape/Annuler leave persisted data unchanged.
- Client fields adapt to Personne/Organisation and keep party type fixed during edit. Nouveau client uses the same primary blue-green treatment as Ajouter un site.
- Create/edit refreshes and selects sensibly; Archive/Restore respects the current filter. No regime control, Delete action, fake row, or contract-creation action exists.
- Permanent navigation remains exactly Contrats, Clients & installations, Paramètres; Contrats and Paramètres remain S0 placeholders.
