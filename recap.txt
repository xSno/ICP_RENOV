Scope and authorities
- Step 3 enables « Générer le DOCX et le PDF » only when authoritative business completeness and generation availability both pass. Opening/cancelling the confirmation remains side-effect free.
- The only new Web generation intent is generateOfficialContract(contract_id). JavaScript presents confirmation, progress, success and failure; Python reruns preflight and owns every official effect.
- Existing DocumentGenerationService, ReviewService, ProductionDocxRenderer, LibreOfficeConverter, PersistedContractNumberAllocator, ContractDocumentRepository and ContractEventRepository authorities are reused.
- The existing isolated-attempt workflow renders and validates DOCX/PDF before one BEGIN IMMEDIATE publication transaction allocates the first official number, publishes immutable Rxx files/snapshot, inserts ContractDocument and DOCUMENT_GENERATED, and changes DRAFT to TO_SIGN. Published files are removed if final persistence rolls back.
- A per-service contract guard rejects duplicate concurrent attempts; the database publication checks remain the final idempotency authority.
- Planned first numbers are unreserved previews read before rendering. Planned Rxx is computed from the authoritative persisted ContractDocument revisions before rendering.
- Cross-contract safety uses safe outcome B: the final BEGIN IMMEDIATE transaction serializes writers; PersistedContractNumberAllocator recomputes and conditionally advances numbering_settings, and DocumentGenerationService requires the claimed number to equal the rendered preview. A stale attempt raises number_changed, rolls back the counter claim and all official effects, then a new invocation re-previews and re-renders safely.
- Revision publication re-reads the exact durable revision list inside the same transaction and requires it to equal the pre-render list. Database UNIQUE(contract_id, document_kind, revision_index), immutable document rows, contract-state predicates and official-path collision checks provide additional enforcement.
- The persisted Contract number, immutable snapshot number/revision, ContractDocument revision, official filenames and rendered DOCX content are asserted equal after both contended successes.
- The confirmation explains freezing, DOCX/PDF creation, deferred first number/Rxx allocation, TO_SIGN transition, and the complete failure guarantee without implementation jargon.
- Failure results distinguish contract data, model/company, DOCX, PDF and final persistence categories and state that no new revision/first number was created and draft data is preserved.
- No Step 4 UI, CONTRACT_SENT, signature, activation, correction UI, intervention generation, signed revision field, or official-generation side effect outside the complete-success transaction was added.

Interrupted-publication recovery
- A normal Python/SQLite exception after file moves removes the moved files and rolls back the transaction.
- An abrupt process termination after file moves but before commit leaves no authoritative database ContractDocument/event/number/status because SQLite rolls back the uncommitted transaction.
- Retry-time reconciliation runs only inside the existing BEGIN IMMEDIATE publication boundary and only for the exact planned DOCX/PDF targets under the managed documents/contracts tree. This serialization prevents a retry from touching another live publisher's in-flight files.
- A target referenced by any persisted ContractDocument docx_relpath, pdf_relpath or signed_pdf_path is authoritative: it is preserved and the existing collision error remains.
- An exact managed target with no repository owner is interrupted residue: it is moved into the isolated current attempt directory, then normal attempt cleanup removes it. No workspace scan, startup recovery, arbitrary-file cleanup, number/revision/status mutation or event is introduced.
- Simulated hard termination after R01 file moves leaves DRAFT, no number, no ContractDocument/event and an unadvanced counter; retry reconciles both orphans and publishes exactly one consistent R01 while consuming exactly one number.
- Persisted R01 is explicitly classified authoritative and remains byte-identical. Simulated orphan R02 is reconciled after reopen, and retry publishes the real R02 without advancing the first-number counter again.
