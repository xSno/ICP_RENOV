ICP RENOV - CONTRACT MANAGEMENT APP - S6 RECAP

Implementation
- Migration 6 preserves migrations 1-5, rebuilds the ContractDocument table only to allow immutable R02+ indices, and adds the single generic append-only contract_events authority with the full canonical event vocabulary, foreign keys, indexes, immutability triggers and document-scope insertion protection.
- Backfill is deterministic: one CREATED event uses each existing Contract.created_at_utc, and one DOCUMENT_GENERATED event uses each existing CONTRACT ContractDocument.generated_at_utc and exact document id. No sending or unsupported event is inferred; reopening the database creates no duplicate.
- New Contract creation persists Contract + Conditions + exactly one CREATED event in one transaction. Event failure leaves no partial Contract.
- Every successful official revision persists its DOCUMENT_GENERATED event in the existing atomic publication transaction. Event failure rolls back DB changes and removes the newly placed pair.
- Documents & suivi is the functional fourth step for every Contract. A never-generated DRAFT shows “Aucun document” and its creation history. Revisions are newest-first with readable template/version, generation date, restrained latest/previous wording, revision-specific sent marker and safe DOCX/PDF/folder opening.
- Paths are resolved from workspace-relative persistence and must remain inside the configured workspace. A missing DOCX or PDF keeps the immutable revision visible, disables only that action and shows “Un fichier du contrat est introuvable”; the other file remains usable. Opening a screen, file or folder creates no event.
- Corriger le contrat uses a bounded confirmation and atomically appends REOPENED_FOR_CORRECTION while changing TO_SIGN to DRAFT. The official number, previous revisions, snapshots, hashes and sending history are preserved; no revision is created by reopening.
- A reopened DRAFT is a valid numbered/editable state. Steps 1 and 2, Review and Documents & suivi remain functional; the landing shows the retained number, Brouillon and the latest unsigned revision.
- Later generation derives the next Rxx from durable CONTRACT documents, reuses the official number and never calls NumberAllocator. R02/R03+ preserve all prior revisions. Inconsistent number/document/revision states and file collisions fail closed.
- R02+ readiness remains within the four accepted Review checks. Review and confirmation show the retained number and next revision; the first-number allocator may be unavailable for an already-numbered correction.
- Failed R02 renderer, DOCX postflight, conversion/PDF, DB publication, event insertion and collision cases leave DRAFT + existing number + byte-identical R01, with no R02 files/document/event; the next success still creates R02.
- Enregistrer un envoi records an action performed outside the application. CONTRACT_SENT requires an exact existing CONTRACT revision and real effective_date, accepts an optional note, changes no Contract status and supports historical and multiple sends.
- Sent state is derived only from CONTRACT_SENT events for the exact document. R01 sent does not mark R02 sent; the compact marker uses the latest declared sending date and History retains every event.
- History is derived only from ContractEvent, ordered by occurred_at plus stable id tie-breaker, and uses French labels. S6 creates only CREATED, DOCUMENT_GENERATED, CONTRACT_SENT and REOPENED_FOR_CORRECTION.
- No signature, signed PDF, SIGNED/ACTIVE, renewal, termination, intervention-sheet generation or S7 behavior was added.
