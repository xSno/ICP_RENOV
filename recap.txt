BUG-SEARCH-01/02 — Search Focus Preservation

Baseline
- Starting HEAD: 75c8a740cfe096451bd7dbe2f5b0a26c7d3f4e4d (IMP-DS-01D migrate contract workspace visuals).
- Starting worktree: clean.
- Current HEAD: 75c8a740cfe096451bd7dbe2f5b0a26c7d3f4e4d. No commit was created.

Root cause
- Contracts and Clients shared the same rerender lifecycle: input oninput calls the Python UiBridge, the authoritative snapshot refreshes, then WebEngine replaces #app through innerHTML.
- The active search input was destroyed on every character, so browser focus and caret/selection were lost.

Implementation
- app.js gives the two inputs stable identifiers: contracts-search and clients-search.
- Shared captureSearchFocus / restoreSearchFocus helpers capture identity, selectionStart, selectionEnd and selectionDirection only when one of these search inputs is active.
- After the ordinary render, focus and selection are restored only to the recreated matching input. Selection boundaries are clamped to the current input value length.
- No focus is restored when focus had moved elsewhere; Tab and click-away behavior therefore remain native and no focus trap is introduced.
- Python UiBridge filtering, refresh, search matching and routing remain authoritative and unchanged.
