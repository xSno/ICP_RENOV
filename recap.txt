ICP RENOV - CONTRACT MANAGEMENT APP - S7 RECAP

Implementation
- Migration 7 preserves migrations 1-6 and adds the bounded lifecycle_status projection for SIGNED/ACTIVE, nullable signed_pdf_path/signed_pdf_hash/signed_pdf_attached_at metadata, unique SIGNATURE_RECORDED/ACTIVATED authority, required event fields, and a trigger that keeps every core ContractDocument field immutable while allowing only typed signed-copy metadata updates.
- Enregistrer la signature is available only for TO_SIGN with an existing CONTRACT revision and no prior signature. The latest revision is preselected, but the user may explicitly sign an older revision after a clear non-blocking warning. SIGNATURE_RECORDED.document_id is the sole signed-revision authority.
- The selected revision immutable snapshot is the sole authority for contractual start_date. Missing/invalid snapshot start dates fail closed; live Contract data and the latest revision are never substituted.
- Contract.signature_date is a read-only repository projection of SIGNATURE_RECORDED.effective_date. No editable or duplicate signature-date persistence exists.
- If signed snapshot start_date is future, signature atomically produces SIGNED and no ACTIVATED. If reached, signature atomically appends SIGNATURE_RECORDED then ACTIVATED, uses snapshot start_date as ACTIVATED.effective_date, and produces ACTIVE.
- Activation reconciliation runs at startup, Contracts refresh and Contract opening/Documents refresh. It is date-provider driven, idempotent, never reverses ACTIVE, creates no duplicate, and exposes a storage notice if a due transition cannot persist. No Activate action exists.
- Signed PDF is optional. When supplied, it is validated as a readable/non-empty PDF, staged, copied to documents/contracts/<contract-id>/<Rxx>/signed/<unique>.pdf, hashed SHA-256 and persisted with archival timestamp in the same logical signature publication. The external source is untouched; failure leaves TO_SIGN, no signature/activation and no official orphan.
- Signature without copy remains valid and shows “Signature enregistrée — copie signée non archivée” plus “Ajouter le PDF signé”. Adding it later updates only signed-copy metadata and creates no ContractEvent.
- Missing and hash-mismatched copies preserve signature, metadata and lifecycle status. Localiser requires the original stored hash and preserves hash/attached_at; Ajouter une nouvelle copie uses a new unique path/hash/attached_at. Neither action creates a ContractEvent.
- History uses SIGNATURE_RECORDED and ACTIVATED business entries plus one display-only “Copie signée archivée” row derived from signed_pdf_attached_at. Signed state is shown only on the exact event-linked revision; “Dernière révision” remains independent.
- After signature, structured services remain locked, Corriger le contrat is unavailable and defensively rejected, and official generation rejects any later Rxx even under inconsistent status. Historical CONTRACT_SENT recording remains available and status-neutral.
- Contracts landing and Documents & suivi render Brouillon / À signer / Signé / Actif, exact signed/latest revision truth, future-effective information and valid/missing/mismatched copy states without introducing a new screen or workflow.

Remaining S7 risks only
- The application archives the user-declared signed PDF and checks file integrity by SHA-256; electronic-signature/certificate authenticity is intentionally not verified.
- Date-driven activation runs at bounded local application entry points rather than a background scheduler; a workstation that is not opened cannot persist the due transition until the next entry point.
- A due activation that cannot write local storage remains durably SIGNED and requires a later successful reconciliation; there is intentionally no manual activation fallback.
- Real Company and first-number providers remain intentionally unavailable in default composition; the smoke uses accepted synthetic providers. OS file opening still depends on workstation file associations.

No changes under docs/, templates/ or spike/. No commit. No renewal, termination, intervention-sheet workflow or S8 implementation.
