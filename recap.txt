ICP RENOV - CONTRACT MANAGEMENT APP - S3 RECAP

Migration / schema
- Migrations 1, 2 and 3 are preserved unchanged. Explicit migration 4 adds contract_templates, contract_template_versions, contract_conditions and nullable Contract template/version references.
- Existing S2 drafts receive one empty conditions row during migration. Migration 3 -> 4 and reopen are deterministic/idempotent; latest schema version is 4.
- DRAFT conditions remain nullable/incomplete. No number, revision, lifecycle event, document or readiness structure was added.

Template catalog foundation
- Typed ContractTemplate and ContractTemplateVersion metadata covers functional name, document kind/type, exact status, exact allowed regimes, context authorization, defaults and controlled option catalogs.
- Statuses remain TO_VALIDATE / AVAILABLE / ARCHIVED with no production seed. Current Habitation/Copropriété/Professionnel DOCX candidates were not registered as AVAILABLE.
- Only AVAILABLE + exact contract type + exact regime matches are offered for new selection. CONSUMER, NON_PROFESSIONAL and PROFESSIONAL are never inferred or treated as equivalent.
- A selected version later archived remains referenced and reopenable, with a visible unavailable warning; it is not silently replaced.

Regime / model / legal context
- Regime remains nullable and Contract-only; Client master remains regime-free.
- Regime changes atomically clear an incompatible model plus stale conclusion/early-performance context, while preserving unrelated entered Conditions.
- Model changes apply typed defaults only to empty fields and never overwrite or destroy non-empty user values.
- Conclusion mode appears only when the selected version metadata explicitly requires it for the recorded regime.
- Early performance appears/is accepted only for an exact regime + conclusion combination authorizing both BLOCK_WITHDRAWAL and BLOCK_EARLY_PERFORMANCE. There is no legal inference fallback or expression engine.

Service Conditions
- Persists visits, refrigerant mode, included area, business hours, travel included, priority breakdown/delay, DEEP_CLEANING, DISINFECTION and additional exclusions.
- Baseline maintenance is displayed as included and cannot be unchecked. No extra V1 service option exists.
- Priority delay is absent and cleared when priority breakdown is not included.
- Travel canonical-field result: only service.included_area and service.travel_included are persisted. No undocumented service.travel_* detail field was invented.

Period / pricing / payment
- STANDARD stores start date + month count and calculates calendar end date as anniversary minus one day. CUSTOM stores start date + explicit Date de fin and clears the contradictory month source.
- Covered examples: 01/09/2026 + 12 months = 31/08/2027, month-end and leap-year-safe cases.
- Pricing persists only annual HT and a catalog-controlled VAT rate. VAT and TTC are calculated Decimal projections and cannot be independently overridden.
- Payment terms/methods come only from typed version catalogs; raw codes are not rendered. Due days/custom text are shown and retained only when their selected term authorizes them.
- Missed-appointment fee remains nullable (« Aucun ») or a validated non-negative amount.

Renewal / early termination / special terms
- NONE clears/hides all dependent renewal data. MANUAL supports duration, price rule and internal alert while clearing notice/channels. TACIT additionally supports contractual notice/channels.
- FIXED and NEW_PRICE_ON_RENEWAL are accepted; INDEXED is rejected and absent from the UI. Internal alert and non-renewal notice remain distinct.
- Early-termination reasons, custom text and cure period use a secondary in-app right drawer backed by version catalogs; no termination action/event exists.
- Special terms remain line-break-preserving plain text with no HTML/Markdown/rich interpretation.

Conditions UI
- Step 2 « Conditions du contrat » is functional with the seven bounded sections. Steps 1 and 2 are enabled; Revue and Documents & suivi remain unavailable.
- Regime/model empty states, model filtering, conclusion/early-performance context, priority delay, STANDARD/CUSTOM dates, payment dependencies and renewal fields react by true show/hide behavior.
- Save success appears only after a successful SQLite transaction; structured validation keeps visible entries available for correction.
- No regime in Client master, Review content, generation button, numbering, revision, native dialog or top-level editor was introduced.

DEVELOPMENT VISUAL SMOKE ONLY
Run these commands from the repository in one PowerShell session. They redirect both machine bootstrap state and business data to a disposable TEMP folder and create only explicitly synthetic metadata:

$smokeRoot = Join-Path $env:TEMP 'ICP_RENOV_S3_VISUAL'
$env:LOCALAPPDATA = Join-Path $smokeRoot 'LocalAppData'
$env:ICP_S3_WORKSPACE = Join-Path $smokeRoot 'Workspace'
@'
import os
from pathlib import Path
from icp_renov_contracts.bootstrap import build_application_context
from icp_renov_contracts.config import BootstrapConfig, MachineConfigStore
from icp_renov_contracts.domain import ContextAuthorization, ControlledOption, PaymentTermOption, TemplateDefaults, TemplateOptionCatalogs, TemplateValidationMetadata, TemplateVersionStatus
store = MachineConfigStore()
store.save(BootstrapConfig(Path(os.environ['ICP_S3_WORKSPACE'])))
ctx = build_application_context(config_store=store)
template = ctx.template_catalog.create_template('SYNTHÉTIQUE — VISUEL S3')
ctx.template_catalog.create_version(template, 'visual-1', TemplateVersionStatus.AVAILABLE, ('CONSUMER',), TemplateValidationMetadata(('CONSUMER',), (ContextAuthorization('CONSUMER', 'OFF_PREMISES', ('BLOCK_WITHDRAWAL', 'BLOCK_EARLY_PERFORMANCE')),)), TemplateDefaults(visits_per_year=2, included_area='Île-de-France', business_hours='8h–18h', travel_included=True), TemplateOptionCatalogs(('5.5', '20'), (PaymentTermOption('DUE', 'À échéance', True, False), PaymentTermOption('CUSTOM', 'Modalité personnalisée', False, True)), (ControlledOption('TRANSFER', 'Virement'), ControlledOption('CARD', 'Carte')), (ControlledOption('EMAIL', 'E-mail'), ControlledOption('POST', 'Courrier')), (ControlledOption('BREACH', 'Manquement'), ControlledOption('OTHER', 'Autre'))))
print('Métadonnées SYNTHÉTIQUES S3 créées dans', os.environ['ICP_S3_WORKSPACE'])
'@ | python -
python -m icp_renov_contracts

Cleanup after closing the application:

Remove-Item -LiteralPath (Join-Path $env:TEMP 'ICP_RENOV_S3_VISUAL') -Recurse -Force
Remove-Item Env:ICP_S3_WORKSPACE -ErrorAction SilentlyContinue
Remove-Item Env:LOCALAPPDATA -ErrorAction SilentlyContinue

Remaining S3 risks only
- Real production versions legitimately remain unavailable until their separate validation/governance workflow marks them AVAILABLE.
- Final subjective visual acceptance of the full Conditions form remains for the user on the target workstation.
- Template/model management and company availability governance intentionally remain absent.
- Review/generation will later own completeness and readiness checks; S3 deliberately saves incomplete drafts.
